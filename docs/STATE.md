## Architecture / facts the next agent must know

- **Clean Architecture + Cubit**, DI via `get_it` in [`lib/core/di/injection.dart`](../lib/core/di/injection.dart). Features: `auth`, `orders`, `tracking`, `shell`, `splash`, `wallet`, `profile`. Routing is `go_router` in [`lib/core/router/app_router.dart`](../lib/core/router/app_router.dart).
- **Boot order:** `main.dart` → `DeliveryBootstrap` (Firebase init; in **debug** a branch/project picker first) → `DishFlowDeliveryApp` → router. In debug the picked branch is stored in SharedPreferences `_dev_firebase_client`; switching branch on Android **cold-restarts** the app (Android can't delete the default Firebase app).
- **`geocoding` 5.0.0 removed all top-level functions.** There is no `locationFromAddress()` / `placemarkFromAddress()` any more — you must construct `Geocoding()` and call the instance method. `Location`/`Placemark` still resolve because they are re-exported from `geocoding_platform_interface`, so a stale call site fails with **only** `undefined_method` on the function and looks like a bad import. See [`order_location_resolver.dart`](../lib/features/orders/domain/utils/order_location_resolver.dart) — the instance is created **lazily** because `Geocoding()` goes through `GeocodingPlatformFactory.instance!` and would throw if built in a static field initializer before plugin registration.
- **Branding = one active asset, filled by a script.** The app reads exactly one logo at runtime: `brand_assets/active/icon.png` (`AppAssets.brandLogo`). `scripts/apply_brand.ps1 -Brand <b>` copies `deploy_configs/<b>/icon.png` into it, rewrites the Android label/applicationId + iOS `CFBundleDisplayName`, then regenerates launcher icons and the native splash. **Same mechanism as the customer app** (`../dishflow-kingdom-multiresturant-mobile`) — keep them in sync. Full notes in [`deploy_configs/README.md`](../deploy_configs/README.md).
- **`AppColors.brandPrimary` treats `0xFFFF6B35` as "not set"** and falls back to the driver blue `primary300` (`#009DE0`) — see [`app_colors.dart`](../lib/core/theme/app_colors.dart). That value is exactly what the **balkans** brand ships as `PRIMARY_COLOR`, so the Balkans build renders blue, not its orange. Pre-existing quirk, deliberately left alone; any other value overrides correctly.
- **Splash is two layers.** Native (`flutter_native_splash`, brand logo on white — replaces the default **Flutter logo** that Android 12+ takes from the launcher icon), then the animated Dart [`SplashPage`](../lib/features/splash/presentation/pages/splash_page.dart). Routing off the splash is owned by [`SplashGate`](../lib/features/splash/presentation/splash_gate.dart), **not** the page.
  - `SplashGate.done` **latches**. It must: `AuthLoading` also fires when the driver taps "Log in", so a non-latching gate bounces the user from the login form back to the splash.
  - `app.dart` subscribes to `_authCubit.stream` **before** calling `bootstrap()` — the reverse order can miss the first settled state and hang the splash forever.
- **Map / route (`DeliveryMapView`)** — [`delivery_map_view.dart`](../lib/features/orders/presentation/widgets/delivery_map_view.dart):
  - Markers are **painted at runtime**, not bundled PNGs — [`MapMarkerFactory.pin()`](../lib/core/utils/map_marker_factory.dart) draws a pin on a `Canvas` with a MaterialIcons glyph and returns `BitmapDescriptor.bytes(...)` at the device pixel ratio (cached per icon/color/size). Customer = `Icons.person_rounded` on `#F2711C`; driver = `Icons.delivery_dining_rounded` on the brand color. Both use `anchor: (0.5, 1)` because the art is a pin with its tip at the bottom.
  - Driver position is a **live `Geolocator.getPositionStream`** (25 m `distanceFilter`). The route is only recomputed when the driver has moved ≥ **150 m** or ≥ **45 s** has passed (`_shouldReroute`) — do not remove this throttle, every recompute is a billed API call.
  - **Route provider = Google Routes API** (`routes.googleapis.com/directions/v2:computeRoutes`, POST + `X-Goog-FieldMask`). The **legacy Directions API is disabled** on this Google Cloud project — it answers `REQUEST_DENIED / "You're calling a legacy API"`. Do not "fix" the route by going back to `maps.googleapis.com/maps/api/directions/json`; it cannot work here.
  - **The Routes call never actually succeeds today — by decision, not by bug.** Two gates were found and only the first is solved: (1) the Android app restriction, now handled by sending `X-Android-Package` / `X-Android-Cert` from [`AndroidApiKeyHeaders`](../lib/core/utils/android_app_identity.dart); (2) **billing is not enabled** on the key's project `970110791123`, and the owner chose not to enable it. So every run takes the labelled straight-line fallback, and **Navigate → Google Maps** is the real directions feature. An unrestricted key via `--dart-define=MAPS_API_KEY=…` remains a valid alternative if it belongs to a billed project.
  - **Fallback is intentional and visible**: no Routes answer → straight line, distance = great-circle × **1.35**, ETA at **25 km/h**, polyline drawn `geodesic` + dashed, and the ETA card shows an "approx." tag. `isEstimate` is the flag; never present an estimate as a real route.
  - Polyline decoding is hand-written in [`order_route_resolver.dart`](../lib/features/orders/domain/utils/order_route_resolver.dart) (no extra package). Locked by tests against Google's documented example string.
- **Auth is TEMP and insecure by decision** (see `README.md`): driver username/password live in plaintext in Firestore `drivers`; the app signs in **Anonymously** to Firebase and then matches the `drivers` doc. Anonymous Auth must be enabled per Firebase project.
- **`TrackingRepository` is still a stub** ([`stub_tracking_repository.dart`](../lib/features/tracking/data/repositories/stub_tracking_repository.dart)) — `start()`/`stop()` only flip a bool. Nothing is written to RTDB `driver_locations/{uid}` yet, despite `AppConfig.gpsInterval` existing. The live GPS in `DeliveryMapView` is **local to the map**, not the broadcast tracker.
- **Branch ≠ brand, currently.** There are **14** Firebase branch configs in `lib/firebase_configs/` (`kDevFirebaseClients` in [`firebase_project_selector.dart`](../lib/core/dev/firebase_project_selector.dart)) but only **3** `deploy_configs/` brands (`balkans`, `cairo_kaiser`, `dev`), and only 2 of those ship an `icon.png`. A branch with no brand folder keeps whatever `brand_assets/active/icon.png` currently holds.
